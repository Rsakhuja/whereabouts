Methodology

How the test set was built, how answers are scored, and what's kept private and why.

The taskTest setScoring What's publishedLimitations

The task

A model is shown one street-level photo with no caption, metadata or follow-up questions, and asked to reply in JSON with:

  • country
  • state or province: the first-level division (a US state, a Japanese prefecture, a Brazilian estado)
  • city: the nearest city, town or village
  • features: 3–5 visual features that led to the guess

Every model gets the same prompt. Reasoning modes are off unless a leaderboard row says otherwise. Each model answers each photo once. When photos are added, models are run on the new photos only, and the date each photo was run is recorded. A model only appears on the leaderboard once it has answered every photo in the current set.

The test set

76 photos, one per city, across 48 countries and six world regions. The cities are mostly large capitals and regional centres, from Lagos and Lahore to Montevideo and Melbourne.

The photos are Street View views captured by hand in 2026, one location per city, mostly chosen to show an ordinary street scene. Each has a hand-written answer key: country, first-level division and city.

Screening

Every photo was checked against written, quality-only criteria. A photo is rejected if it is:

  1. blurry or smeared so the main scene can't be made out
  2. too dark or overexposed to see the street
  3. mostly blocked by a vehicle, wall, windscreen or close-up object
  4. not outdoors at street level
  5. not actually in the labelled city
  6. showing an unblurred face or licence plate

Being too easy (a famous landmark, a sign naming the city) or too hard (a generic street) is not a reason to reject: easy photos are tagged instead. Photos are never added, swapped or removed after seeing how models did on them.

A caveat, stated plainly: the photos were picked by hand before these criteria were written down, and were checked against them afterwards. Future batches are screened against the criteria from the start. Some photos still carry faint Street View watermarks or small map icons. These don't reveal the location, and if a model cites them as a feature, the Features page counts that separately.

Scoring

One point each for the right country, state or province, and city, out of 3 per photo. The headline score is total points divided by the maximum.

Matching place names

Models write place names freely, so answers are matched through a hand-built list of names and spellings for every place in the answer key. For example:

  • "Bengaluru" counts as Bangalore, "Saigon" as Ho Chi Minh City, "CDMX" as Mexico City
  • "Praha", "Wien" and "Türkiye" count as Prague, Vienna and Turkey
  • local-script answers such as "東京" or "서울" count as Tokyo and Seoul
  • a guess like "Suginami-ku, Tokyo" earns the state point (Tokyo) but not the city point: naming a ward is not naming the city

A name that isn't on the list scores zero for that level. The list only needs to cover the correct answers, since any other place is wrong anyway.

Refusals and errors

A reply that declines to answer, or answers "unknown" for all three levels, counts as a refusal and scores zero, and is shown as wrong on the leaderboard. Results are only published once every photo has a reply.

Uncertainty

With 76 photos, each photo is worth about 1.3% of the score. The range under each score is a 95% bootstrap confidence interval (5,000 resamples of the photo set). When two models' ranges overlap heavily, the benchmark can't reliably tell them apart.

What's published, and what isn't

The photos, the answer key and each model's individual guesses are kept private. Only totals are published: scores, per-level accuracy, region breakdowns and feature-type counts. Two reasons:

  • Contamination. A public test set with answers can end up in future training data, and then high scores could mean memorisation rather than skill.
  • Licensing. The photos are Street View captures, which aren't ours to redistribute. Using them privately and publishing only aggregate scores keeps that use minimal.

The code is public: the runner, scoring, the place-name list and this site. Anyone can run it on their own photos.

Limitations

  • Small. 76 photos is enough to separate strong models from weak ones, not to rank models a few points apart.
  • Big cities only. Every answer is a major city, which makes guessing the city easier than it would be for random locations. Rural and small-town performance isn't measured.
  • Uneven regions. Asia and the Middle East have 33 photos, Oceania has 2. Region scores for small regions are rough.
  • One photo per city, one answer per model. There is no repeat sampling yet, so run-to-run variation isn't measured. Photos added later are answered later, so a model's results can span several dates; providers normally keep versioned model IDs fixed, but this is worth knowing.
  • Possible prior exposure. These exact captures aren't online, but the places are on Street View, which models may have seen in training.
  • Hand-picked. Curation keeps quality consistent, but a person chose every view. The written criteria and the rule against swapping photos after seeing results are there to limit that bias.
  • Claimed features aren't verified. See the Features page caveats.
